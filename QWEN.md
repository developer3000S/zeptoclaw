# QWEN.md — ZeptoClaw Agent Mesh

Instructional context for working in this repository. Read before making changes.

## Project overview

**ZeptoClaw Agent Mesh (`zeptomesh`)** is a fully decentralized P2P network of autonomous
AI agents built on [PicoClaw](https://github.com/sipeed/picoclaw). Nodes form a mesh with no
central coordinator and no shared database: a task can arrive at any node, be executed
locally or recursively delegated to neighbors, and the result returns to the originator over
the traversed route.

Implemented against the Russian-language spec [`ТЗ.md`](ТЗ.md) ("PicoClaw Agent Mesh", v0.1).
The project is a **working daemon**: networking, discovery, routing, tasks, admin API, CLI,
tests, and installers are written, compile, and pass tests. Honest status against the spec is
tracked in [`docs/STATUS.md`](docs/STATUS.md).

**Primary language of the repo docs (README, docs/, comments, this file): Russian.**
Go identifiers, CLI signatures, env vars, and protocol names stay in English.

### Key properties

| Area | Implementation |
|---|---|
| Network layer language | Go 1.26 (`go.mod` declares `go 1.26.0`) |
| Node identity | Ed25519, self-attested libp2p `PeerID` |
| Transports | QUIC (primary) + TCP (fallback). **With PSK set, node runs TCP-only** (go-libp2p QUIC does not support private networks) |
| Encryption | Noise (TCP), TLS 1.3 (QUIC) |
| Message format | Protobuf v3, length-prefixed frames (8 MiB ceiling) |
| Discovery | local Unix-socket registry · mDNS · bootstrap nodes · Kademlia DHT · Peer Exchange |
| Membership | GossipSub (`PeerState`) |
| Storage | BadgerDB v4 (node-local) + content-addressed artifacts |
| Delegation | TTL, loop-free route, dedup, fan-out/parallelism limits, rate limiting |
| Task decomposition | `subtasks` / `--subtask` plan → child envelopes → single signed aggregate result |
| Signatures | `TaskEnvelope`, `TaskResult` (+`worker_signature`), `TaskAck`, `CancelRequest`, `Capabilities`, `origin_signature`, `KeyRebind`, `SkillsSyncResponse` |
| Executor | PicoClaw via adapter: CLI process / Pico Protocol (WebSocket) / offline stub |

### Architecture (high level)

One node = mesh daemon + local PicoClaw + node-local storage. No central components;
`bootstrap.*` are optional network entry points.

```
HTTP/JSON (admin API) → internal/api
  → internal/tasks (Manager: receive → validate → execute | delegate → result)
      → internal/picoclaw (Adapter: stub | cli | pico-ws) → PicoClaw
  → internal/routing (table, scoring, candidate selection)
  → internal/p2p (libp2p Host + task/result/rpc Service)
  → internal/discovery (local | mDNS | bootstrap | DHT | gossip)
  → internal/security (identity, signing, trust, ratelimit, audit journal)
  → internal/storage (BadgerDB + artifacts/sha256)
```

There are **two separately-built binaries**:
- `zeptomesh-node` — the agent daemon + CLI (primary, documented in README).
- `zeptomesh-ui` — a newer **web dashboard BFF** (see [UI dashboard](#ui-dashboard) below).
  Installed independently in Docker via `install-ui.sh`; only talks to the node admin API.

## Build / run / test

`make` targets are self-documenting (`make help`). Direct `go` commands also work.

```bash
export PATH=$PATH:/usr/local/go/bin

make              # fmt-check + vet + build + test  (standard check)
make ci           # local CI equivalent: static-check + build + test-race
make build        # agent daemon → bin/zeptomesh-node
make build-ui     # dashboard BFF → bin/zeptomesh-ui
make cross        # linux/{amd64,arm64} (ТЗ 15.1)
make test         # all tests (also: test-race, test-cover, test-unit, test-integration, test-load, bench)
make proto        # regenerate gen/ from api/proto (needs protoc + protoc-gen-go)
make lint         # golangci-lint if installed; else gate = vet + gofmt
make dev-cluster / dev-status / dev-rotate / dev-cluster-down
make install-local / install-docker / docker-build / docker-build-ui / install-ui
```

Equivalents without Makefile:

```bash
go build ./...
go vet ./...
gofmt -l .            # empty output = formatted
go test ./...         # unit tests (internal/{wire,security,skills,routing,discovery,config,tasks,p2p})
go test -race ./...
go build -trimpath -o bin/ ./cmd/zeptomesh-node
```

**Important — Go toolchain version.** The `go` directive in `go.mod` must stay
`go 1.26.0`. If it is lowered below 1.22, `http.ServeMux` method patterns like
`"GET /healthz"` silently become literal paths and ALL method routes return
`404 page not found` despite correct code. The local `go` on this machine may
be old (e.g. 1.19.8) — to build/test with the right toolchain run through
Docker:

```bash
docker run --rm -v "$PWD":/src -w /src golang:1.26 bash -c 'go test ./...'
```

## Development conventions

- **Config** is YAML, loaded by `config.Load`: `config.Default()` → `${VAR}` /
  `${VAR:-default}` expansion (incl. nested defaults) → YAML → env overrides
  (`ZETOMESH_BOOTSTRAP` appends to `discovery.bootstrap`) → `Validate()`.
  Secrets are never written into config files; they come from env (bearer
  tokens named via `auth_token_env`, `token_env`, etc.).
- **Signatures / canonical encoding**: do not bypass `internal/wire` — the
  canonical encoder is shared between a task's digest and its signature so the
  two can never diverge. Results add `worker_signature` computed over
  route-independent fields; relays must not rewrite it.
- **Trust/access model**: trust levels (open/limited/private), allowed/blocked
  peer files enforced at `ConnectionGater` level, `allow_shell` defaults to
  `false`; subtask constraints are the intersection of parent's constraints
  (`tasks.DeriveSubtask`). Tasks can only lose rights, never gain them.
- **PSK (private network) ⇒ TCP-only**: any code that adds a libp2p transport
  (webtransport, webrtc, …) must check PSK compatibility at host startup, or
  quiet breakage of closed networks returns. See `internal/p2p/host.go` and the
  `quic_disabled_private_network` warn.
- **Terminal journal states are truth**: `COMPLETED`/terminal entries are
  written first (guarded by `Terminal()` + `journalMu`); transitional fields
  (`DelegatedTo`, `Attempts`, `FORWARDED`) are appended by async post-ack
  bookkeeping and may land AFTER the terminal record. Tests must assert on the
  "settled" state (worker != "" AND len(DelegatedTo) > 0) and accept either
  `FORWARDED|COMPLETED` for status — never weaken the invariants themselves.
- **Generated protobuf is committed** (`gen/`) so `go build ./...` works
  without `protoc`. Regenerate only via `make proto`; keep `gen/` in sync
  (`make proto-check` is a CI gate).
- **PicoClaw CLI contract** (verified upstream): `picoclaw agent` accepts only
  `-d/-m/-s/--model`; unknown flags crash it; model knobs (temperature, max
  tokens, etc.) are env-only (`PICOCLAW_AGENTS_DEFAULTS_*`); the Pico WS outbound
  `message.send` carries no model. In the adapter: `picoclaw.model` is a
  node-level param applied only in `binary` mode as `--model`; other knobs go
  under `picoclaw.env`. Do not invent raw flag passthrough.
- **Module path / repo**: the canonical repo is
  `git@github.com:developer3000S/zeptoclaw.git` (SSH origin; don't switch to
  HTTPS). Go module path is `github.com/developer3000S/zeptoclaw`. Anything
  under `github.com/zeptoclaw/*` or `github.com/zeptomesh/...` is WRONG.
  The binary name `zeptomesh-node` and proto package `zeptomesh/v1` are
  historical and must not be renamed. New files must use the correct module
  path.

## UI dashboard

The dashboard is a **separate BFF binary/image** that observes and manages the mesh without
touching agent config. It polls the admin APIs of configured nodes, merges their view into one
network graph, serves an embedded vanilla HTML/CSS/JS UI, and proxies operator actions back to
a chosen node. It exists because the admin API has **no CORS**, the API token must not reach
the browser, and the BFF merges multiple nodes into one graph.

- Entry point: `cmd/zeptomesh-ui/main.go`. Package: `internal/ui/` (config, nodes client,
  aggregator, server; `static/` embedded via `go:embed`). No new go.mod deps — stdlib only.
- All config is environmental (docs/UI.md §4):

  | Env | Default |
  |---|---|
  | `ZETOMESH_UI_LISTEN` | `127.0.0.1:28090` |
  | `ZETOMESH_UI_NODES` | empty (seed list) |
  | `ZETOMESH_UI_NODES_FILE` | `<data>/nodes.json` (persistent, editable from UI) |
  | `ZETOMESH_UI_TOKEN` | empty (this UI's own auth) |
  | `ZETOMESH_UI_API_TOKEN` | empty (bearer for nodes lacking their own) |
  | `ZETOMESH_UI_POLL_INTERVAL` | `5s` |
  | `ZETOMESH_UI_DATA` | `./zeptomesh-ui-data` |
  | `ZETOMESH_UI_LOG_LEVEL` | `info` |

- **Default dashboard port is 28090** (mesh port 4001, admin API 8081, Prom metrics 9464).
- Backend API: `GET /healthz` (HEALTHCHECK), `GET /api/v1/mesh` (cached network snapshot),
  managed-node CRUD (`/api/v1/nodes`), and proxied operator actions against a chosen node.
- Two visibility levels: **managed** nodes (explicit endpoint list, editable from UI) vs
  **discovered** peers (union of all managed nodes' `/api/v1/peers` → the "whole created
  network"). A discovered peer whose `peer_id` equals a managed node's `peer_id` (from
  `/healthz`) is marked managed.
- Install: `./install-ui.sh` (auto-detect nodes | `--host-gateway` | `--nodes …`),
  `make install-ui`, `make docker-build-ui`. Image: `zeptomesh-ui:latest`, separate compose
  project `zeptomesh-ui` connecting to the agent network `zeptomesh_default` (default mode) or
  host gateway. Installation/deletion touches ONLY the UI container/image/stack.
- **Note:** `cmd/ui/main.go` is a minimal health-check-only stub used only by the **root
  `Dockerfile`** (which builds `ui-server` from `./cmd/ui`). The real production dashboard
  image is `deploy/ui/Dockerfile` (builds `cmd/zeptomesh-ui`). Do not confuse the two; the root
  `Dockerfile` is not the dashboard's canonical build.
- Go version gate (see above) applies here too: the UI uses ServeMux method patterns, so
  `go.mod` must stay >= 1.22.

## Testing

- **Unit**: `go test ./...` over `internal/{wire,security,skills,routing,discovery,config,tasks,p2p}`.
- **Integration** (ТЗ 17.2 + special 17.4): `make test-integration` — `-race -tags=integration`
  over `internal/node/... internal/security/...`.
- **Load** (ТЗ 17.3, 100/500/1000 nodes): `make test-load` → `internal/simulator` → tee to
  `load-test-output.txt`; see `docs/LOADTEST.md`.
- **Live acceptance** (ТЗ §20 E.1–E.6): `scripts/acceptance.sh` on real processes.
- **Bench**: `make bench` (routing + canonical encoding).
- CI: `.github/workflows/ci.yml` (static, cross-build linux/{amd64,arm64}, unit `-race`,
  integration race + stress `-count=2`, live acceptance, native arm64 runner, Docker image
  build). `make ci` is the local fast-subset equivalent.
- Full inventory / mapping / known defects: `docs/TESTREPORT.md`; coverage table in
  `docs/STATUS.md`.

## Environment / deployment quick reference

- `install.sh` — agents: local (systemd, user or system units) or Docker; N instances
  numbered from 0. Ports: mesh base `4001`, API base `8081`, Prom base `9464`; random free
  5-digit ports by default (or sequential from `ZETOMESH_BASE_*`). Supports `--nodes`,
  `--mode`, `--yes`, `status|start|stop|uninstall`.
- `install-ui.sh` — dashboard (see UI section above).
- `update.sh` — updates from the repo (short wrapper; check its contents before relying on it).
- `.env.example` — LLM provider & chat-channel env vars for PicoClaw (not used by the Go daemon
  itself; it's the PicoClaw side).
- Runtime data: node keys `<data_dir>/keys/peer.key`, run sockets `<data_dir>/run`,
  BadgerDB `<data_dir>/db`, audit journal `<data_dir>/audit/security.jsonl`, skills
  `<data_dir>/skills.json`, rebind log `<data_dir>/rebinds.json`.
- Working tree currently contains `bin/` and `zeptomesh-ui-data/` (runtime artifacts).

## Quick-start (two nodes, one machine)

```bash
go build -trimpath -o bin/ ./cmd/zeptomesh-node
bin/zeptomesh-node genkey --out ./n0/keys/peer.key   # and the same for ./n1
ZETOMESH_DATA=./n0 ZETOMESH_INDEX=0 bin/zeptomesh-node run -config configs/node.yaml &
ZETOMESH_DATA=./n1 ZETOMESH_INDEX=1 ZETOMESH_MESH_PORT=4002 \
  ZETOMESH_API_PORT=8082 ZETOMESH_PROM_LISTEN=127.0.0.1:9465 \
  bin/zeptomesh-node run -config configs/node.yaml &

bin/zeptomesh-node status  -addr http://127.0.0.1:8081
bin/zeptomesh-node peers   -addr http://127.0.0.1:8081
bin/zeptomesh-node submit  -addr http://127.0.0.1:8081 -i "hello" -w
```
