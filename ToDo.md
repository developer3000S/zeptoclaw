15. **Исправить: `install-nodes.sh --nodes 4` создаёт только одну ноду** — ✅ готово
    - Первопричина: в цикле ожидания готовности первой ноды (`install_docker`)
      стояло `((waited++))`. В bash `((expr))` возвращает статус **1**, если
      значение выражения равно 0, а `((waited++))` при `waited=0` как раз даёт
      0 → с `set -euo pipefail` скрипт прерывался сразу после старта `zepto-0`,
      и ноды 1..3 (`docker compose up -d` остальных) не запускались никогда
    - Исправлено на `waited=$((waited + 1))`; та же ловушка устранена в
      `find_free_port` (`((port++))`/`((attempt++))` → `x=$((x + 1))`)
    - Попутно исправлен дефект bootstrap в `generate_docker_compose`: раньше
      ноды получали невалидный адрес `/ip4/127.0.0.1/tcp/zepto-0:<порт
      текущей ноды>` (DNS-имя внутри multiaddr + порт не якорной ноды), а
      якорная нода — адрес самой себя. Теперь нода 0 — якорь с пустым
      bootstrap, остальные получают `zepto-0:<mesh-порт якоря>` (Rust-нода
      разбирает `host:port` и резолвит имя через DNS docker-сети; peer_id
      берётся из handshake, `/p2p/<id>` не нужен)
    - В сервисы добавлен `image: zeptomesh-node:latest` — compose переиспользует
      заранее собранный образ вместо сборки отдельного образа на каждую ноду
    - Убран устаревший атрибут `version: '3.8'` из генерируемого compose-файла

    - Исправлено на `security::verify_key(&vk, …)` — вариант для
      self-certifying PeerID, где прото-оболочка не нужна (3 места в `node.rs`:
      `absorb_capabilities`, `handle_search_request`, `handle_search_reply`)
    - Тот же дефект касался подписи search-запросов/ответов: подпись всегда
      считалась некорректной, relay-search не работал

18. **Исправить сходимость mesh: изоляция нод и пустые `peer_id`** — ✅ готово
    - **Пустой `peer_id` у соседей (корневая причина «неполного» mesh)**:
      в `routing.rs::Table::upsert` запись клалась в карту под ключом
      `peer_id`, но само поле `cur.peer_id` **не заполнялось** и оставалось `""`
      из `Default`. Отсюда каскад: пустые id в `GET /api/v1/peers`, пустые id
      в gossip (ноды заводили друг другу записи под пустым ключом), сломанные
      `trust_of("")` и выбор кандидата для делегирования
    - **Ретрай bootstrap-диала**: в `node.rs::start()` диал был одноразовым —
      нода, стартовавшая раньше якорной, оставалась изолированной навсегда
      (scan по умолчанию выключен). Теперь диал повторяется с backoff
      2 с → 30 с, пока якорь не ответит
    - **Peer exchange**: gossip передаёт адреса соседей (`PeerState.addrs`),
      но никто по ним не dial'ил. Добавлен `dial_known_peers()` — нода
      докаливает пиров, с которыми ещё нет живого соединения, поэтому mesh
      доходит до полного, а не остаётся звездой от якоря
    - **Объявление routable-адреса**: ноды объявляли соседям bind-адрес
      `0.0.0.0`, по которому `connect` уходит в localhost (то есть нода
      подключалась сама к себе). Теперь в Docker объявляется IP контейнера
      (`HOSTNAME` → `/etc/hosts` → `getaddrinfo`), а `0.0.0.0` отсекается
      перед dial
    - **Защита от мусорных записей**: пустые `peer_id` отбрасываются в
      `gossip_round`, `absorb_gossip`, обработке search-ответа и в
      `Table::restore()` (запись без id из BadgerDB больше не поднимается)
